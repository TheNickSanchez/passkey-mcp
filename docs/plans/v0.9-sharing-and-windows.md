**Part 2 — Architectural Design Decisions**

**2.1 Inline Encrypted Token Sharing (`passkey share` + `passkey upload`)**

* **CLI Ergonomics & Fuzzy Matching (`passkey share [query] [fields...]`)**
  * Signature: `passkey share [entry] [fields...] [-f/--fields FIELDS...] [-o/--output FILE] [--shared-by NAME] [--no-passphrase] [--prompt-passphrase] [--no-copy]`
  * Entry Resolution: Calls `resolve_entry(args.entry, "Select entry to share", fuzzy=True)` ([handlers.py](file:///Users/nick.sanchez/projects_personal/passkey/passkey/cli/handlers.py#L10-L65)).
    * `passkey share` (no args) -> opens fuzzy interactive entry picker.
    * `passkey share jamf_api_admin` or `passkey share jamf` -> resolves exact or unique fuzzy match in **0 extra prompts**, or opens pre-filtered picker if multiple entries match `"jamf"`.
  * Field Filtering Interaction:
    * Positional `fields` (`nargs="*"`) and `--fields/-f` (`nargs="+"`, comma- or space-separated) are merged and deduplicated.
    * If explicit fields are supplied, validate each against `entry.fields` (and `entry.config` if explicitly requested). If a positional token is not a field on `entry` *and* matches another entry name in `list_entries()`, raise an explicit `PasskeyError` explaining that positional args after `<entry>` filter fields and pointing to `passkey export <file> --encrypt --entries ...` for multi-entry bundles.
    * If no explicit fields are supplied: single-field entries auto-select their sole field immediately; multi-field entries in interactive mode show `questionary.checkbox` with **all fields pre-checked (`checked=True`)** so pressing `Enter` shares the entire entry in 1 keystroke.
  * Mode Selection (`--output` vs. Inline Default):
    * `--output <path>` supplied -> writes legacy binary `PK01` `.enc` file (`O_CREAT | O_EXCL`, `0o600`), preserving 100% backwards compatibility.
    * `--output` omitted (default) -> generates compact `pk1:...` token, copies to clipboard via `copy_with_autoclear` (`120s` default; `60s` when `--no-passphrase` is set), and prints a clean human summary + the generated 8-word passphrase (zero unnecessary prompts unless `--prompt-passphrase` is passed).

* **`pk1:` Wire Format Specification**
  * **String Encoding:** `"pk1:" + base64.urlsafe_b64encode(raw_frame).rstrip(b"=").decode("ascii")` (URL-safe `[A-Za-z0-9_-]`, unpadded, immune to Slack/Teams/Discord markdown formatting; decoder strips all whitespace, newlines, and surrounding quotes before adding `=` padding).
  * **Binary Frame (`raw_frame`):**
    * `Byte 0` (`uint8`): `TOKEN_VERSION = 0x01`
    * `Byte 1` (`uint8`): `flags` bitmask:
      * `0x01` (`FLAG_ZLIB`): inner UTF-8 JSON is compressed with `zlib.compress(data, level=9)`.
      * `0x02` (`FLAG_EMBEDDED_KEY`): `--no-passphrase` mode; bytes `2..33` hold a raw 256-bit `AESGCM` key (`os.urandom(KEY_LEN)`) instead of a Scrypt salt.
      * Bits `2..7`: reserved (`0`; decoder rejects `flags & ~0x03 != 0` to fail closed on unknown future flags).
    * `Bytes 2..33` (`32B`, `SALT_LEN` / `KEY_LEN` imported from [bundle.py](file:///Users/nick.sanchez/projects_personal/passkey/passkey/bundle.py#L20-L28)): Scrypt `salt` (when `FLAG_EMBEDDED_KEY == 0`, derived via `bundle._derive_key(passphrase, salt)`) or `embedded_key` (when `FLAG_EMBEDDED_KEY == 1`).
    * `Bytes 34..45` (`12B`, `NONCE_LEN` imported from [bundle.py](file:///Users/nick.sanchez/projects_personal/passkey/passkey/bundle.py#L21)): `AES-256-GCM` random nonce (`os.urandom(12)`).
    * `Bytes 46..end`: `AESGCM(key).encrypt(nonce, payload_bytes, associated_data=b"pk1:" + header_0_to_46)` (includes `16B` GCM authentication tag; binding `"pk1:" + header` as AAD prevents bit-flipping `version` or `flags`).
  * **Compact Inner JSON Payload:**
    `{"v": 1, "n": entry.name, "f": secret_fields, "c": config_fields, "p": entry.policy, "by": shared_by, "at": iso_ts}` (omitting empty `"c"`, `"by"`, and default `"p": "allow"`).
  * **Size Benchmarks:**
    * Fixed framing + crypto overhead: `1 + 1 + 32 + 12 + 16 = 62 bytes` (~87 chars with `pk1:`).
    * 1-field API token (`stripe`): ~147 binary bytes -> **~200 chars** (fits in 3 lines on Slack/Teams).
    * 3-field Jamf/AWS credential (`jamf_api_admin`): ~222 binary bytes -> **~300 chars** (well under Discord's 2,000-char, Slack's 4,000-char, and Teams's 28,000-char limits).
    * 2 KB PEM private key: ~1,512 binary bytes -> **~2,020 chars**.
  * **Decompression Safety:** Enforce `MAX_TOKEN_PAYLOAD_BYTES = 262_144` (`256 KiB`) via `zlib.decompressobj().decompress(pt, MAX_TOKEN_PAYLOAD_BYTES + 1)` *after* GCM tag verification to eliminate zip-bomb DoS.

* **`passkey upload` & Upgraded `passkey receive` UX**
  * Signature: `passkey upload [file] [--as NAME] [--mode {ask,skip,overwrite,merge}]` (`passkey receive` becomes an alias to the same handler with `file` changed to `nargs="?"`).
  * **Argv Secret Guard (Landmine #2):** Positional `file` accepts file paths only. If `file` starts with `"pk1:"`, immediately raise `PasskeyError(..., error_code="INVALID_USAGE")` refusing `pk1:` tokens in CLI `argv` and instructing the user to run bare `passkey upload` and paste at the masked prompt.
  * **Interactive Paste & Auto-Detection:** When `file` is omitted, prompts via `prompt_secret("Paste pk1:... token (or .enc file path)")`. Normalizes pasted passphrases (`"-".join(raw.strip().lower().split())` when hyphenless multi-word input matches `_PASSPHRASE_WORDS`) so spaces or hyphens both decrypt cleanly.
  * **Preview & Collision Resolution:** Displays entry name, sender/timestamp (if present), policy, and masked field previews (`format_secret_preview`). If `<name>` already exists and `--mode ask` (default), prompts via `questionary.select`:
    1. `Merge / update fields into '<name>'` (preserves existing `created`, `policy`, `config`, and unshared fields)
    2. `Overwrite '<name>'` (replaces `fields`, preserves `created` and `policy`)
    3. `Save as a new entry name...` (prompts and validates via `_validate_entry_name`)
    4. `Cancel`
  * **Headless AI Agent Blocking:** Both `passkey share` and `passkey upload` / `receive` call `require_interactive(...)` first (exiting `2` for agents/non-TTY) AND are explicitly blocked in [hooks.py](file:///Users/nick.sanchez/projects_personal/passkey/passkey/hooks.py#L95-L145) `_check_shell_command`.

**2.2 Windows Credential Manager Large-Entry Storage (`passkey/keychain.py`)**

* **Constraint:** `WinVaultKeyring` calls `CredWriteW` with `UTF-16LE` encoding (`2 bytes/char` for BMP), failing above `2,560 bytes` (`1,280 chars`).
* **Unified Cross-Platform 3-Tier Envelope (`KEYRING_INLINE_LIMIT_UTF16_BYTES = 2400`, `CHUNK_BASE64_CHARS = 1150`):**
  Running the identical threshold across macOS, Linux, and Windows ensures 95%+ of entries remain plain JSON while large entries exercise the exact same battle-tested compression/chunking code path on every OS and test runner:
  1. **Tier 0 — Plain JSON (`len(raw_json.encode("utf-16-le")) <= 2400`):** Stored verbatim at `(SERVICE, entry.name)`. 100% backwards-compatible with all existing entries.
  2. **Tier 1 — Single-Item Compressed (`pkz1`):** `b64 = base64.b64encode(zlib.compress(raw_json.encode("utf-8"), 9)).decode("ascii")`. Wrapped as `{"_pk_storage":"pkz1","data":b64}`. If `<= 2,400` UTF-16LE bytes (covers ~1.2 KB–5 KB entries), stored in the single `(SERVICE, entry.name)` slot.
  3. **Tier 2 — Generation-Keyed Atomic Chunking (`pkc1`):** For payloads exceeding `2,400` bytes even after compression (up to `MAX_ENTRY_BYTES = 1_048_576`, max `64` chunks):
     * Mint a fresh `gen = secrets.token_hex(4)` (`8` hex chars).
     * Split `b64` into slices of `1,150` ASCII chars (`2,300` UTF-16LE bytes `< 2,560`).
     * **Write chunks first:** Store each slice at `(SERVICE, f"__chunk__:{entry.name}:{gen}:{i}")`. Note that `__chunk__:` contains `:` and leading `_`, which are **disjoint** from `ENTRY_NAME_PATTERN` (`^[a-zA-Z0-9][a-zA-Z0-9._-]{0,63}$`), so chunk items can never collide with user entries and are never written to `entries.json`.
     * **Rollback on failure:** If writing chunk `i` raises `KeyringError`, best-effort delete chunks `0..i-1` of `gen` and re-raise `KeychainAccessError` — the previous `(SERVICE, entry.name)` header and its prior-generation chunks remain **completely intact**.
     * **Atomic pointer flip:** Write manifest `{"_pk_storage":"pkc1","gen":gen,"chunks":k,"sha256":sha256_hex}` to `(SERVICE, entry.name)`.
     * **Garbage-collect prior generation:** If the previous raw value at `(SERVICE, entry.name)` was a `pkc1` manifest with `old_gen != gen`, best-effort delete `__chunk__:{entry.name}:{old_gen}:0..old_k-1` (this also runs when a large entry shrinks back to Tier 0 or Tier 1!).
     * **Delete & Rename:** `delete_entry(name)` inspects raw `keyring.get_password(SERVICE, name)` before deletion; if `pkc1`, deletes all `__chunk__:{name}:{gen}:*` items before deleting `(SERVICE, name)` and updating `entries.json`.
     * **Read & Integrity:** `_get_entry` detects `_pk_storage`: `pkz1` decompresses with `MAX_ENTRY_BYTES` cap; `pkc1` reads all `k` chunks (raising `EntryCorruptedError` if any chunk is missing or `sha256` mismatches), decompresses, and passes the reconstructed JSON string to `Entry.from_json(name, json_str)`.

**2.3 Windows Native Secret Capture (`passkey/request_secret.py`)**

* **Architecture:** Mirror macOS (`osascript -`) and Linux (`zenity --password`) by executing the blocking Win32 `CredUIPromptForWindowsCredentialsW` call inside a dedicated stdlib worker subprocess: `[sys.executable, "-m", "passkey.request_secret", "--win-credui-worker"]`.
  * **Why a worker subprocess instead of an in-process `ctypes` call?** Win32 `CredUIPromptForWindowsCredentialsW` has no native timeout parameter, and Python cannot terminate a blocked native C thread. Running it in a child process with `subprocess.run(..., timeout=timeout)` guarantees deterministic `proc.kill()` cleanup and `REQUEST_TIMEOUT` enforcement when `timeout` expires, without wedging the FastMCP stdio server!
  * **Zero-Argv / Zero-Disk Transport:** Dynamic strings (`PASSKEY_REQ_TITLE`, `PASSKEY_REQ_PROMPT`, `PASSKEY_REQ_USER`) pass strictly via child environment variables; the unpacked secret writes strictly to binary `stdout` over an anonymous pipe and is never logged or echoed.
* **Win32 `ctypes` Contract (`credui.dll`, `ole32.dll`, `user32.dll`):**
  1. **Interactive Desktop Check:** Call `user32.GetProcessWindowStation()` + `user32.GetUserObjectInformationW(hwinsta, UOI_FLAGS=1, ...)` (`USEROBJECTFLAGS.dwFlags & WSF_VISIBLE == 0x1`). In Session 0 / non-interactive SSH without a visible window station, exit with sentinel code `3` -> parent raises `PasskeyError(..., error_code="GUI_UNAVAILABLE")`.
  2. **Pre-pack Username so Focus Lands in Password Box:** Call `credui.CredPackAuthenticationBufferW(0, f"{entry_name}/{field_name}", "", ...)` using the standard two-call size query (`ERROR_INSUFFICIENT_BUFFER = 122`). Passing this buffer as `pvInAuthBuffer` pre-fills the target identifier in the Windows Security dialog and places the user's cursor directly inside the masked Password field.
  3. **Prompt:** Populate `_CREDUI_INFOW` (`cbSize=sizeof(_CREDUI_INFOW)`, `hwndParent=user32.GetForegroundWindow()`, `pszMessageText=prompt_text[:32000]`, `pszCaptionText=caption[:120]` — respecting `CREDUI_MAX_CAPTION_LENGTH = 128`, `hbmBanner=None`) and invoke `credui.CredUIPromptForWindowsCredentialsW(byref(info), 0, byref(auth_pkg), in_buf, in_size, byref(out_buf), byref(out_size), None, CREDUIWIN_GENERIC=0x1)`.
  4. **Unpack & Zero Memory:**
     * Return `ERROR_CANCELLED (1223)` -> exit code `2` -> parent records `CANCEL_COOLDOWN_SECONDS` and raises `REQUEST_CANCELLED`.
     * Return `ERROR_SUCCESS (0)` -> two-call `credui.CredUnPackAuthenticationBufferW` to extract `pszPassword` of arbitrary length. Immediately scrub native buffers via `ctypes.memset(pw_buf, 0, ctypes.sizeof(pw_buf))` and `ctypes.memset(out_buf, 0, out_size.value)` before calling `ole32.CoTaskMemFree(out_buf)` (and zero `in_buf`).
